# R2 offline workflow

This release processes supplied review fixtures, stores verifiable artifacts,
and reopens them in a new process. It does not call AI or configure a memory
service. Its `VERIFIED_OFFLINE` result establishes the declared offline checks,
not universal semantic correctness or live provider readiness.

Keep both ZIPs together after extraction. Run from the memory-integrity root:

```powershell
python -B scripts/memory_integrity_workflow.py offline-run --claude-mon-root "../claude-mon" --source "input.txt" --task "Review every declared unit" --responses-file "reviews.json" --run-dir "run-001"
python -B scripts/memory_integrity_workflow.py verify --claude-mon-root "../claude-mon" --run-map "run-001/run-map.json" --source "input.txt" --query every
```

For a simple short UTF-8 file, each line has an ID U000001, U000002, etc.
Oversized lines split into UTF-8-safe child units; obtain IDs from the companion
partition manifest rather than guessing. Reviews JSON is an exact ID mapping:

```json
{"U000001":{"interpretation":"Your actual review of that unit","findings":[],"disposition":"resolved","reviewer":"named-reviewer","unresolved":[]}}
```

Each supplied review must be nonempty and cover the declared set exactly. Empty
input, missing reviews, unresolved reviews and wrong IDs are rejected. No review
is generated by this workflow. In a real audit, establish review quality with
independent challenge cases; do not use invented fixture interpretations.

The saved run includes frozen source, manifest, task/profile, scope, extraction,
semantic review evidence, SQLite ledger and content-addressed requests/responses/
measurement/source proofs. The run-map binds their hashes and generation. Current
source hashes and accepted result identity are rechecked before recall/report.
All/every/totals/absence display enumerates every declared unit; it does not
generate a semantic answer. Other queries are substring locators.

Re-running with unchanged task/profile/source/fixture re-verifies and resumes
without dispatch. Changed basis is historical/stale, not silently replaced.
An incomplete directory is retained and blocks blind resend. Use a distinct
scratch directory only after inspecting the prior state and deciding recovery.

Beads projections are pure SHADOW plans with zero writes. ACTIVE/native database
execution is intentionally unavailable in this release. Installing either skill,
promoting over an installed copy, or qualifying one live call needs separate
authorization.

Tests use Python standard-library unittest. Release packages include their own
preservation baseline and exact content manifest; no original H0/OneDrive folder
is required. Both companion packages are required for the integration tests.
