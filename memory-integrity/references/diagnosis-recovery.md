## 1. Diagnose before repair

Use the smallest observation that identifies the failing layer.

Do not respond to every "forgot" symptom by adding more memory, more embeddings, or larger context.

## 2. Symptom matrix

| Symptom | First hypothesis | Confirming observation | Recovery |
|---|---|---|---|
| File uploaded but answer omits sections | selective retrieval/context | no complete coverage ledger | run complete-read protocol |
| PDF page appears empty | extraction | page exists in original but no canonical elements/text | re-extract/vision inspect; mark extraction partial |
| Search misses known memory | scope/index | direct id exists, search absent | inspect scope/index; do not duplicate blindly |
| Memory disappears after restart | persistence | bridge canary absent | fix data directory/persistence before trust |
| Recall returns old fact | staleness | source hash/version advanced | reread source and supersede derived memory |
| 100% count but missing source range | duplicate accounting | IDs/ranges reveal duplicate + gap | reject count-only proof |
| Model call truncated | context budget | input/output token or transport limit hit | repack smaller deterministic batches |
| Repo map omits implementation | retrieval abstraction | map has signatures/tags only | open actual file/source |
| Synthesis contradicts source | semantic failure | claim's cited unit says otherwise | reopen claim and dependent conclusions |
| Resume repeats work | receipt/state issue | completed identities not checkpointed | restore append-only receipt state |

## 3. Source failures

### Hash changed

Verdict: `STALE`.

Do not carry old receipts forward. Re-ingest current canonical source and compute a new basis.

### Chunk file corrupt

Verdict: `INVALID`.

Regenerate chunks from the canonical source; do not patch corrupted chunks by hand unless the regenerated bytes match the canonical hash.

### Missing extraction elements

Verdict: extraction `PARTIAL` or `ERROR`.

Coverage over the incomplete canonical representation may still be complete, but overall remains blocked.

### Unsupported encoding

Fail closed or use a declared conversion pipeline that records original bytes and normalization rules. Never silently decode with replacement characters.

## 4. Context/retrieval failures

### Too much candidate context

Use exact token accounting and deterministic priority ordering.

Do not solve by silently dropping the tail without recording skipped candidates.

### Aider/Graphify finds likely relevant files only

That is normal selective retrieval. For ordinary coding tasks, direct-read the nominated sources. For complete-read tasks, enumerate the required set separately.

### Unknown tokenizer/model mapping

Require explicit encoding or provider metadata. Do not infer an encoding because a model name looks similar.

## 5. Memory failures

### Liveness fails

`BLIND`. Use direct sources/project state only.

### Write fails

`BLIND` for memory persistence. Do not pretend the fact was saved.

### Write succeeds, recall fails

`DEGRADED`. Investigate index update and scope.

### Direct id succeeds, recall fails

Index/scope failure is likely. Avoid re-saving duplicates as a workaround.

### Recall succeeds, delete ghost remains

`DEGRADED`. Index cleanup is inconsistent.

### Bridge fails after restart

Persistence contract failed or wrong instance/data directory was used. Inspect operational configuration before trusting any historical recall.

## 6. Resume failures

At resume:

1. load canonical project state;
2. audit source registry;
3. verify source basis;
4. identify pending/noncomplete chunks;
5. verify memory if prior-session facts are needed;
6. continue only unresolved work;
7. never infer completed work from a prose note alone.

If the source basis changed during interruption, reopen affected tasks before continuing.

## 7. Performance failures

For large sources measure:

- hashing throughput;
- chunk/unit manifest size;
- receipt append/read time;
- resume scan time;
- tokenization throughput;
- peak memory;
- retrieval latency;
- AgentMemory recall latency at scale.

If verbose manifests become too large, move to compact interval or Merkle representations while preserving exact gap/duplicate/staleness proof.

Do not abandon verification simply because the first representation is verbose.

## 8. Stop conditions

Stop and report `BLOCKED` rather than inventing success when:

- authoritative source is unavailable;
- extraction completeness cannot be established for required content;
- hashes/identities conflict;
- receipt ledger is corrupt;
- required source changed and reread has not happened;
- token configuration is unknown and exact fit matters;
- memory scope cannot be identified;
- the semantic claim cannot be supported by direct source evidence.
