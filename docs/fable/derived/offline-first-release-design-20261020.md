## Recommended mechanism and alternatives

Reuse the source-linked partition/inventory, companion ledger, public workflow
and existing lexical/LSA worker. First repair the demonstrated process/resource
defect with regression evidence. Introduce an explicit offline-first release
profile that refuses native mutations at actual supported dispatch boundaries;
package and test the resulting matching pair as a new release.

- No-build: keep c398be7 and use only the existing controlled development
  workflows. Viable for experiments, but does not deliver a portable tested pair
  or establish installed behavior.
- Selected: small lifecycle repair, restrictive release profile, portable
  acceptance and new paired artifacts. Preserves hybrid code without requiring
  native qualification or a new dependency/model.
- Stronger hybrid: finish native fencing/merge and learned-model evaluation.
  Separate future scope; it does not address the current packaging mismatch and
  is unnecessary for this release's memory/retrieval goal.

Weak link: behavior in a clean extracted pair and the Windows lifetime defect
remain unproven. Cheapest falsifiers are the existing distributed runtime tests,
an independently authored handle-order control, and a relocated public workflow.
Stop and re-plan if those require a toolchain/security change, a new authority
service, deletion of preserved material, or three evidence-changing failed
repair cycles. Do not quietly substitute a reduced support claim.

## Release behavior and limits

Proposed release ID: offline-first-v1; matching engines 2.0.0-m13. Preserve the
Semantica 0.7.0 revision and all approved dependency pins. Host/core CI remains
Python 3.11-3.14; runtime coverage is Windows/Linux Python 3.12 and 3.13. Do not
claim that all host versions have a numerical runtime. Single-worker lexical
search is the documented default when the selected runtime is available; LSA is
optional with no superiority claim. Graph stays opt-in, not automatically ready.

The release includes both single and distributed-local execution for lexical/
LSA retrieval; single is the default and distributed-local is explicit opt-in.
Both execution modes' current regression suites are mandatory release gates,
including Windows 3.12 and 3.13. The representative task's quality obligation is
single-worker source-linked search, mandatory source reopening, save/resume,
stale/access/budget/tamper refusal, and honest status/reporting; a distributed
correctness pass does not establish better discovery or coding benefit.
Preserve other hybrid implementations and their tests;
do not label their broad coding benefit verified merely because they exist.
The distributed-local defect must be repaired and its existing tests pass before
shipping that implementation. If repair fails, ask before changing the release
to enforced single-worker-only support. Do not add skips to obtain a pass.

Offline reviews remain TEST_ONLY; byte coverage is not semantic understanding.
No autonomous live-provider response generation, learned-model download, OCR,
new vector database, global hook, automatic context injection or native Beads/
Dolt execution is part of this build. An assistant must explicitly reopen saved
records in a fresh conversation; no permanent extension of model context exists.

## Native containment without rewriting history

Add an active_release_profile object to each package's capability document:
id=offline-first-v1, native_subprocesses_enabled=false,
native_mutations_enabled=false, live_provider_enabled=false.
Historical granular native qualification facts remain present and unchanged.
They are historical evidence, not authority to override the active profile.

Use package-local release_profile validation helpers, not a new ledger/service.
All Beads/Dolt subprocesses are disabled in this profile, including read-only
backend observation, live readback and reconciliation. Check before subprocess
dispatch and before supported native
reservation/approval consumption and acceptance of new native outcomes. Cover
SharedNativeClaimAdapter.execute/_run, practical native consumers/backends,
lease mint/dispatch entrypoints and companion native reservation/acceptance.
Disk-only historical journal/snapshot inspection and offline fixture coordination
remain usable; they must not contact Beads/Dolt or turn an old UNKNOWN into a
new APPLIED/accepted result. Existing uncertain operations remain frozen until
a separately approved future native profile permits qualified reconciliation.
Any pilot/script advertised as a supported entrypoint must honor the
same restriction before creating a database/server or starting a native binary.
No caller argument, diagnostic JSON or environment variable enables mutations.

Missing/malformed new-profile metadata fails closed for a new-profile package.
Old archived package bytes remain unchanged and keep their historical behavior;
do not run an old binary or adapter and claim the new profile controls it.
Fixture protocol tests remain substantive. Reconcile any existing test that
expects an enabled native operation against this explicit changed profile,
retaining the old contract test/history; no blanket skips, fake success or lost
negative assertions. Raw external bd/Dolt invocations and arbitrary local code
editing are outside this application-level policy, not an OS sandbox guarantee.

## Windows worker lifecycle repair

Inspect _Session creation, pipe-writer lifetime, subprocess inheritance and
DistributedClient.__call__ finalization together. Test all-session shutdown
before temporary-resource disposal; do not assume this is the cause without a
failing control. Close/reap every owned process and join owned writer activity
on success, timeout, killed worker, partial initialization and error paths.
Retain original error context and report cleanup failures honestly. Do not
solve WinError 32 with ignore_errors, blanket retries, widened timeouts or test
skips. Do not terminate unrelated processes or relax OS security controls.

No local test/harness may delete ANY files, including newly created ephemeral
output. New verifier extraction/output directories are retained unique paths,
not TemporaryDirectory contexts with automatic cleanup. Existing tests that
auto-clean must run only through an explicitly inspected retention wrapper,
including detaching automatic finalizers. Record every adaptation and output.
For lifecycle tests substitute a nondeleting Windows handle-access check at the
cleanup boundary: prove workers/handles are closed without removing the file.
This tests handle lifetime, not successful physical deletion. If any existing
case cannot be run faithfully this way, report the exact missing observation.
Do not infer its pass. Do not add a production retention service or change normal
user-runtime cleanup solely to accommodate this campaign's test constraint.

Clean hosted CI remains a separate gate. Before a push/CI authorization, disclose
whether the existing workflow uses auto-cleaning test-owned temporary resources
and obtain explicit permission for that cleanup, limited to that hosted run's
new ephemeral resources. Without it, the exact-CI gate stays BLOCKED even if the
local retained tests pass. No such cleanup permission is granted by this design
draft. Disk growth of retained local results is reported; exceeding the frozen
run budget blocks further work rather than triggering deletion.

## Delivery and installation boundaries

Local source/test/package work requires approval of this full design and task
plan. Existing runtime use needs no reinstall, but inaccessible WindowsApps
Python is a host boundary: prepare a new reviewed host command if necessary,
never substitute Python or reuse consumed N3 commands.

Commit and push require separate approvals for the exact reviewed diff/branch.
Observe required CI on that final commit; no skip-ci label or manual workflow
dispatch is implied. Public release upload is separately approved. Prefer
content/package hashes plus an external commit attestation, avoiding self-hash
or future-commit rebuild loops.

Installation is a later gate: choose Codex or OpenCode, inventory the current
pair, retain rollback bytes, approve the exact target/write, then use a
side-by-side pair and observed installed smoke. A user-led fresh AI session must
load the skill/checkpoint and cite sources; this is separate from Python tests.

## Completion criteria

- Supported memory/retrieval requirements map to non-vacuous public-path tests.
- Active profile refuses deferred native mutations with zero dispatch/approval
  consumption, including direct supported APIs and packaged paths.
- Lifecycle controls and the required existing runtime matrix pass without
  hiding Windows failures; every skip/expected failure has a named disposition.
- Portable source and clean-extracted fixture workflow passes with bound source
  identities and preserved unaffected work; no unsupported semantic claim.
- One fresh independent release review, with an observed repair test for every
  important accepted finding. Existing N3 review is not reused as release review.
- New paired artifacts match their manifest and the exact published candidate;
  old data, releases and failed evidence remain intact.
- Installed readiness is false until the separately approved target smoke and
  user-led fresh-session check are observed.
